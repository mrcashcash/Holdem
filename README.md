# Text Hold'em — heads-up AI learning playground

A two-player, text-first Texas Hold'em table built to make reinforcement-learning experiments easy to run and inspect. The browser hosts a human-versus-agent table; the Python server owns the game rules and can train its baseline agent through self-play.

## What is included

- No-limit heads-up Hold'em: blinds, four betting streets, legal min-raises, short all-ins, folds, ties, and hand evaluation.
- FastAPI JSON API with a single active browser game.
- A recurrent PyTorch PPO agent that learns strategic betting sequences through a curriculum and an Elo-rated champion league. The poker engine remains independent from the learning code.
- React/Vite terminal-style user interface and an in-app self-play training control.

## Run locally

Open two terminals at the repository root.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload --port 8000
```

```powershell
Set-Location frontend
npm install
npm run dev
```

Open the local address printed by Vite (normally `http://localhost:5173`). The frontend proxies `/api` calls to FastAPI during development. Self-play accepts 10 to 500,000 hands per requested run. Once started, it runs in an app-owned worker rather than the originating browser request, so it continues if the page refreshes; keep the backend process running for the duration.

## Hand history from a screenshot

Install the backend requirements, then pass a full-resolution screenshot to the
standalone extractor. A desktop screenshot of the **Hand Replay** dialog with
the complete action timeline visible gives the best result.

```powershell
python tools/screenshot_to_hand_history.py C:\path\to\hand.png
```

The command writes `<name>.hand-history.json` and `<name>.hand-history.txt`
beside the screenshot. It recognizes the simulator's card artwork, reads the
visible action timeline, and replays those actions through the rules engine.
It exits with code `0` for a valid, completed replay, `3` when output was
created but is partial or needs manual review, and `1` when extraction fails.

Use `--starting-stacks PLAYER_1 PLAYER_2` when the hand did not start at
2,000/2,000. If automatic timeline detection is wrong, pass
`--timeline-crop left,top,right,bottom`; fractional coordinates from `0` to `1`
work across resolutions. The script never invents actions that are not visible,
so a clipped timeline is explicitly marked incomplete.

## RTX / CUDA training

The trainer uses CUDA automatically when a CUDA-enabled PyTorch build detects an NVIDIA GPU. With an RTX 3060, PPO batches and optimizer updates run on the GPU. CUDA rollout inference uses a safe single collector on Windows while the rules engine remains CPU-driven.

Install a CUDA-enabled PyTorch wheel using the current Windows command from the [official PyTorch selector](https://pytorch.org/get-started/locally/), then verify it with:

```powershell
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

The backend defaults to `HOLDEM_DEVICE=auto` and `HOLDEM_ROLLOUT_INFERENCE_DEVICE=auto`. Force CUDA for the current PowerShell session with `$env:HOLDEM_DEVICE = 'cuda'`, or use `$env:HOLDEM_DEVICE = 'cpu'` to disable it. `HOLDEM_ROLLOUT_WORKERS` optionally caps CPU rollout processes; the default is up to four workers. With CUDA rollout inference, training deliberately runs one collector worker to avoid CUDA process contention. The training panel reports the selected device, rollout collector, and current/peak VRAM use.

## Learning model

> Historical design notes follow. They describe pre-v25 experiments; the **Current training system (v25)** section is authoritative for the active action space, reward scale, and solver status.

The learner is a legal-action-masked GRU actor-critic with a discounted external-sampling MCCFR auxiliary system. Its observation includes exact visible card identities, board texture, made hands, draws, stack pressure, public betting history, explicit public-belief features, and a bounded Monte Carlo equity estimate sampled from an opponent range. At showdown, revealed opponent cards supervise a 1,326-combination exact range head, retaining suit and blocker information. Before every action, the engine saves a public pre-action context and complete public context history; a recurrent likelihood head learns `P(action | public sequence, exact private combination)`. Card removal plus those learned likelihoods form the reach-weighted belief state used by counterfactual chance resampling. The actor samples a legal continuous raise fraction from a Beta distribution whenever it raises, then clamps it into the rules engine's current minimum/maximum no-limit range. In pressured pots, the live agent samples posterior opponent worlds, evaluates a curriculum-scaled set of legal root actions through learned-policy continuations, and picks a robust value that penalizes uncertainty while blending PPO confidence with positive CFR advantage. Counterfactual branches use progressively larger world/action/depth budgets, current learned policies for continuation, and a slowly updated target network with uncertainty-aware distributional value leaves. Stratified replay prioritizes rare, high-regret, and recent decisions instead of training uniformly from the CFR reservoir. A bounded self-imitation buffer distils only high-margin winning decisions as a small auxiliary loss, never as off-policy PPO data. PPO uses GPU minibatches and CUDA mixed precision when available; a KL/clip/entropy controller adjusts learning rate, policy clip range, and exploration pressure from observed update behavior. A quality-gated lifetime curriculum advances from short stacks to deep stacks only after the policy reaches readiness targets. Three rotating learner profiles use different exploration/learning-rate settings, cross-play through the league, and periodically mutate the weakest profile from champion state. A payoff-driven regret-matching PSRO-style Elo league mixes frozen champions, fixed exploiters, and diverse retained neural best responses. Promotion uses sequential balanced-seat evaluation plus a fixed holdout suite spanning short-stack, deep-stack, pressure, and late-street seed sets.

Version 15 separates public features from private blocker and board-card inputs, then combines recurrent memory with causal action attention. Its CFR branches carry exact continuous raise fractions end-to-end; action-conditioned Beta policies are trained from both PPO trajectories and counterfactual sizing targets. CFR+ positive-regret fitting and an independent average-strategy reservoir provide an SD-CFR-style deployment prior. Targeted deterministic deck profiles cover short-pressure, draw-heavy, paired, and monotone boards, while promotion additionally checks a reproducible restricted best-response suite and cross-play robustness.

Version 16 adds a suit-equivariant policy/value card encoder while retaining a raw blocker path for exact-range supervision. A three-member bootstrap value ensemble reports uncertainty to the resolver, which expands its legal no-limit root set from learned sizing, pot landmarks, and stack-commitment thresholds. Counterfactual searches are distilled into a dedicated value replay so local belief solves improve the network rather than disappearing after rollout. A bounded frozen-strategy archive supplies a snapshot ensemble for deployment and league cross-play, while best-response lanes train against the frozen champion more frequently. Turn and river search budgets grow with street pressure and ensemble disagreement.

Version 17 turns evaluation into the scheduler: paired-seed, balanced-seat promotion checks update per-opponent and per-scenario weakness scores, and the next self-play batches focus on those measured weaknesses while preserving exploration floors. Search replay now explicitly samples deep and uncertain resolves, rollout batches adapt to observed collection time, and promotion thresholds require a stronger worst-case holdout and restricted-best-response floor. Optional local teacher data can seed only safe auxiliary memories; place a validated `.jsonl` export in `backend/data/hand_history` and import its filename from the trainer. Each line must contain `observation` (180 numbers), `mask` (9 booleans), `action` (a legal index), and `return_value` (-5 to 5). Optional `context` (10 numbers), `history` (up to 12 contexts), and `range_class` (0..1325) also supervise the public action-likelihood model. No third-party data is downloaded or used automatically.

Version 18 adds PFSP-style opponent selection, fixed audit-only opponents that never enter the training league, and an action-abstraction exploitability proxy that is explicitly reported as a lower-bound audit rather than exact no-limit exploitability. Direct paired-seat evaluations now batch compatible policy states in one forward pass, improving the throughput of the promotion and holdout suite. Curriculum progression also requires a per-scenario decision-quality floor. Fixed-seed evaluation snapshots retain direct, league, holdout, audit, and proxy metrics, so the dashboard shows the change from the previous comparable run instead of relying on a single noisy score.

Version 20 adds a bounded, local tabular CFR+ abstraction teacher. It is explicitly not a solution claim for full no-limit Hold'em: its public street, stack-pressure, texture, and equity-bucket targets are projected onto the rules engine's real legal actions, then distilled as a low-weight auxiliary policy/value loss alongside PPO and Deep CFR. Same-deal swapped-seat rollout pairs reduce variance, while the rollout arena exposes a native-ready capability contract without pretending an unvalidated C++/Rust replacement exists. The dashboard reports oracle replay size, losses, confidence, iterations, pairing coverage, and the active rollout backend.

Version 21 keeps an exact reachable opponent-combination posterior at resolver decision points rather than re-expanding coarse range buckets during chance sampling. Posterior support and entropy control resolver confidence and replay weighting; adaptive raise candidates now also include recent observed opponent sizing. Promotion adds a fixed-seed, seat-swapped blueprint audit and a small tabular Kuhn-poker CFR sanity probe. These are intentionally conservative quality gates, not a claim of exact full-game exploitability. Blueprint and temporary exploit-opponent signals remain separate, so only the robust champion can be promoted.

Version 22 adds a compact, suit-aware public-belief encoder and a range-conditioned counterfactual value head. Resolver world samples supervise only the rank/suit classes actually reached, so unsampled classes remain masked rather than becoming false labels. During a live deep resolve, this value head blends with the existing scalar value ensemble according to posterior concentration and its own uncertainty. A sampled root safety filter rejects action candidates that fall materially below the current blueprint action under the bounded posterior simulation. This is explicitly an approximate guard, not a proof of safe re-solving or exact no-limit exploitability.

Version 23 records per-root posterior outcomes, converts them into lower-confidence action values, and compares those lower bounds with the blueprint action before a live resolver can deviate. Solver replay confidence is also reduced when world samples disagree, so noisy resolve targets do not receive the same distillation weight as stable ones. A fresh champion-seeded exploiter lane periodically learns against the frozen champion; retained exploiters are ranked by measured champion score and their bounded threat signal increases their self-play sampling. These are empirical robustness controls, not exact best responses or a proof of safe no-limit re-solving.

Version 24 turns the local resolver into a bounded multi-iteration regret-matching procedure over sampled public-belief roots. The value learner now consumes both the acting player's degenerate private range and the opponent posterior, supervising paired zero-sum counterfactual value surfaces with sparse masks and uncertainty. The learned Beta sizing policy supplies several legal solver proposals in addition to pot/stack landmarks; difficult late-street states are sampled more frequently into the bounded public-belief teacher replay. These are practical approximations to public-belief search, not an exact ReBeL/DeepStack reproduction, safe solver, or full-game exploitability proof.

Version 19 introduces a native-ready interleaved rollout arena. Every worker now advances multiple independent hands round-robin and batches compatible recurrent policy decisions, while preserving each hand's deck, policy history, legal mask, opponent, and safety limit. The card/range network gains lightweight street adapters so strategy can specialize between preflop, flop, turn, and river without fragmenting shared knowledge. Deeper turn/river public-belief solves receive a dedicated policy-distillation update, teaching both the live and average-strategy heads from high-depth resolver distributions. Deployment reports the active average-strategy blend, arena width, and subgame-teacher loss.

The strategic league and champion are versioned and written to `backend/data/strategic_champion.pt`; they are ignored by Git. Checkpoints include the per-profile optimizer and target state, mixed-precision scaler, CPU/CUDA RNG, scenario curriculum, average-strategy memory, continuous sizing targets, range likelihood data, counterfactual replay, and benchmark results. Older neural checkpoints reset safely. Use the **Train self-play** panel to inspect device/VRAM, action search, scenario coverage, sizing-CFR loss, strategy memory, restricted-BR BB/100, cross-play, and the normal PPO/range/league gates.

## Current training system (v25)

The production learner is a legal-action-masked recurrent PPO actor-critic. It uses a semantic action space—fold, check/call, one legal continuous raise interval, and all-in—so every raise size has one identifiable policy probability. Trajectories retain their true terminal chip return in big blinds; only the critic target is normalized for stability. The value ensemble has a ±200 BB distributional support.

Training uses paired, seat-swapped deals, frozen historical opponents, PFSP-style opponent sampling, and a 20 BB → 40 BB → 100 BB → 200 BB curriculum. Promotion is based on paired BB/100 bootstrap intervals and fixed holdout EV, never hand win-rate alone. Checkpoints are versioned at `backend/data/strategic_champion.pt`; the new action/value representation intentionally resets older checkpoints and replay memories. During training, the trainer saves atomically every 20,000 completed hands by default and retains the preceding checkpoint as `backend/data/strategic_champion.backup.pt`. Startup falls back to that backup when the primary checkpoint cannot be loaded. Set `HOLDEM_CHECKPOINT_INTERVAL_HANDS` to another positive interval, or `0` to disable periodic checkpoints; the normal end-of-run save remains enabled.

**Train self-play** resumes the saved champion. To deliberately start an untrained model, enable **Start a fresh model** in the training panel and confirm the warning. Before the new model is created, the server copies the current primary and backup checkpoints to a timestamped folder under `backend/data/checkpoint_archives/`. These archives are not loaded automatically, so a fresh experiment cannot overwrite the model it replaced.

Every finished run also writes a portable diagnostic JSON report under `backend/data/training_reports/`, plus an atomically refreshed `latest.json`. It contains final telemetry, evaluation history, benchmark/audit results, population and checkpoint metadata, active settings, and explicit gate/vulnerability diagnostics. It intentionally excludes model weights, optimizer tensors, replay records, and private hand histories. Send `latest.json` after a run for a focused training review. If a run stops before its first update, send `backend/data/training_reports/training-debug.jsonl` as well: it records durable API, worker, pool, rollout, learning, cancellation, and report-writing phase events without model or hand data.

The independent fixed-seed promotion, league, adversarial, holdout, blueprint, and preflop audit matches run concurrently on CPU during evaluation. Fixed-style and preflop audits also interleave independent hands and batch their policy forwards, while restricted-best-response and audit-proxy styles are independently scheduled then reduced to the same worst-case BB/100 result. Sequential promotion checks retain their loaded candidate and opponent models across the existing 16-hand batches. This leaves every deal seed, hand count, PPO update, and promotion threshold unchanged; it only reduces wall-clock wait time. `HOLDEM_EVALUATION_WORKERS` controls the evaluator pool (default: up to four CPU workers). Training status and reports expose `rollout_seconds`, `learning_seconds`, `evaluation_seconds`, `checkpoint_seconds`, `parallel_evaluation`, and `evaluation_workers` so each run shows where time was spent.

With CUDA available, fixed preflop root audits use one coordinated GPU inference lane while CPU evaluator processes continue independent rule simulation. The lane is intentionally singular: concurrent CUDA evaluator processes compete for one GPU and are slower in practice. The collector reloads the exact learner and target state every update while reusing only revision-verified frozen opponents. Set `HOLDEM_CUDA_EVALUATION=0` to force the earlier CPU-only audit path. If the GPU lane cannot run, the same fixed audit falls back to CPU rather than weakening or skipping any gate.

On CUDA, the learner uses fused AdamW when the installed PyTorch build supports it, otherwise it falls back to standard AdamW with the same settings. Rollout tensors already use pinned, asynchronous GPU transfers, and the 1,326-combination range lookup remains cached on the training device. A newly requested training run preserves the GradScaler's current numeric scale but resets its transient optimizer bookkeeping, so an interrupted or auto-reloaded run cannot leave the next run marked as already unscaled. Status and reports additionally expose PPO tensor-preparation, transfer, compute, auxiliary-learning, and optimizer timings, plus the active optimizer backend. These are execution changes only: PPO epochs, minibatch update count, samples, and all quality gates remain unchanged.

The range and public-action-likelihood heads learn from public action sequences. In self-play, the known opponent hole cards supervise the exact 1,326-combination posterior at every recorded decision, plus a 13×13 suitedness-class loss; cards are never supplied to the policy input. During live play the agent retains conservative, showdown-safe opponent statistics across hands. The optional local teacher-data schema uses `observation` (180 numbers), `mask` (4 booleans), `action` (0–3), and `return_value` (-200 to 200 BB); optional `context`, `history`, and `range_class` also supervise the likelihood head.

The older bounded resolver and hand-authored abstract oracle remain experimental and are disabled by default because they are not full MCCFR/Deep CFR or safe no-limit solving. Set `HOLDEM_ENABLE_APPROXIMATE_RESOLVER=1` or `HOLDEM_ENABLE_HEURISTIC_ORACLE=1` only for controlled research runs. The Kuhn-CFR audit is retained as a small regression signal, not as evidence of Hold'em exploitability.

The abstract-CFR teacher is a fully enumerated CFR+ game with five private-strength buckets, public street/SPR/texture contexts, real fold/call/raise/all-in sequences, explicit chip commitments, and an exact NashConv calculation for that *abstraction*. It never selects a live action and its NashConv is not Hold'em exploitability. The default robust profile runs it as an ablation (`HOLDEM_ABSTRACT_CFR_TEACHER_MODE=ablate`), so it creates no new teacher targets and does not train from teacher records already in a resumed checkpoint. Set `HOLDEM_ABSTRACT_CFR_TEACHER_MODE=on` for a controlled teacher-on comparison; its low-weight coefficient remains configurable with `HOLDEM_ABSTRACT_CFR_TEACHER_WEIGHT` (default `0.025`).

The robust profile reserves 40% of ordinary population rollouts for retained exploiters and pressure, loose-aggressive, trapper, maniac, nit, and tight-aggressive fixed styles. Set `HOLDEM_ADVERSARIAL_ROLLOUT_FRACTION` between `0.10` and `0.80` to tune that share. Measured worst-case opponents receive a bounded on-policy weight, while a population member must accumulate `HOLDEM_POPULATION_SPECIALIST_MIN_UPDATES` (default `36`) before an exploiter refresh can reset it; `HOLDEM_EXPLOITER_REFRESH_UPDATES` (default `54`) controls the refresh cadence. Population replacement, PFSP pressure, opponent weakness, curriculum readiness, and challenger retention are driven by BB/100 rather than hand-win rate. Curriculum and promotion use direct confidence, league chip EV, adversarial-style floors, restricted best response, and audit BB/100 floors; a 50% self-play score alone cannot advance the agent.

The trainer now focuses `HOLDEM_ADVERSARIAL_FOCUS_SHARE` (default `0.70`) of that adversarial quota on the two styles with the worst measured BB/100 result, while retaining a coverage floor for the other threats. Ordinary screening uses `HOLDEM_ADVERSARIAL_SCREENING_HANDS=512` hands per style; candidates near promotion receive a 2,048-hand-per-style confirmation, while clearly weak completed runs retain their diagnostic audit without spending that confirmation budget. A candidate cannot promote without the same confirmation evidence. PPO applies a bounded extra on-policy policy weight only to adversarial terminal losses of at least `HOLDEM_LARGE_LOSS_BB=6`, while a separate critic-only hard-spot memory learns their values without cloning the losing actions. Full promotion evaluation reports the worst fixed-adversary paired BB/100 lower-confidence bound and requires it to clear `HOLDEM_ADVERSARIAL_PROMOTION_LCB_FLOOR` (default `-32`). A candidate must additionally meet the existing fixed blueprint confidence/floor guard (`HOLDEM_BLUEPRINT_PROMOTION_CONFIDENCE=0.50`, `HOLDEM_BLUEPRINT_PROMOTION_FLOOR=0.48`) before it can replace the champion; otherwise a sufficiently distinct candidate can still be retained as an exploiter. PPO restores the complete update whenever either hard-KL guard trips. A post-step breach retries that already-clipped gradient at an initially half-strength scale and is accepted only after the same hard-KL recheck; accepted retries gently increase that scale while rejected retries reduce it. Status and reports expose the retry decision, tail-risk, critic-memory, confirmation, and behavioral-root-audit diagnostics.

Normal raises in an unopened preflop pot are constrained to the legal interval from the minimum raise through `HOLDEM_PREFLOP_OPEN_RAISE_CAP_BB` (default `10`). This prevents an ordinary open from spanning directly to the full 50 BB stack. When facing exactly one voluntary preflop raise, a normal 3-bet is also capped at `HOLDEM_PREFLOP_THREE_BET_POT_CAP_MULTIPLIER` times the pot immediately before the action (default `2`). If the legal minimum is already larger, the legal minimum is retained; 4-bets, 5-bets, and the separate all-in action remain unrestricted. The same rule applies to the reference, resolver, and compiled rollout paths. Each full evaluation performs fixed-root opening and 3-bet sizing audits, while run-level and rolling adversarial/tail-loss telemetry avoid misleading last-batch-only readings.

Training also forces a configurable share of paired self-play hands into public preflop roots: facing 2–5 BB opens, a 3-bet, or a 4-bet. `HOLDEM_PREFLOP_FORCED_ROOT_FRACTION` defaults to `0.30`; full evaluations play every root against nit and tight-aggressive opponents (`HOLDEM_PREFLOP_SCENARIO_AUDIT_HANDS=128` per root/style, multiplied for the final audit). Their paired BB/100 intervals and action/street diagnostics are written to `training_reports/latest.json`; the weakest root is automatically sampled more often in later rollouts. This improves response coverage without scripting the agent's decision after the public prefix.

Low-commitment preflop all-ins are calibrated with soft PPO probability penalties, never an action mask. The bounded target applies only to blind and single-open decisions before the player has committed `HOLDEM_PREFLOP_ALLIN_COMMITTED_FRACTION` of the starting stack (default `0.50`). Facing 3-bets and 4-bets remains fully legal, but a reserved portion of the same bounded matched-branch teacher budget compares all legal lines on the identical deal; it lowers an all-in only when a legal non-all-in branch is better. `HOLDEM_PREFLOP_3BET_TEACHER_MULTI_RAISE_MIN_ROOTS` reserves 12 of the default 40 comparisons per rollout, including an enforced `HOLDEM_PREFLOP_3BET_TEACHER_FACING_4BET_MIN_ROOTS` floor (default 8) for facing 4-bets; `HOLDEM_PREFLOP_TEACHER_FOCUS_MIN_ROOTS` reserves 12 comparisons for the current worst audited root. A separate matched-branch call-odds correction (`HOLDEM_PREFLOP_TEACHER_FACING_4BET_CALL_CONTRASTIVE_WEIGHT`, default `0.22`) applies only when a legal facing-4-bet alternative is measured better, never as an action mask. Reports retain last-update and whole-run target-vs-actual action mixes by root, so deep all-in samples cannot be mistaken for shallow-open evidence. Forced-root sampling ranks roots relative to their current audit LCBs with a bounded 1.6x focus multiplier. A second binary stability target, weighted by `HOLDEM_PREFLOP_ALLIN_STABILITY_WEIGHT` (default `0.12`), makes a regression toward unsafe early all-ins costly without forbidding committed shoves. Full audits maintain a best measured recovery anchor. A learner rolls back only after two material safety regressions, to that anchor rather than automatically to the deployed champion. Fixed-root audits record the candidate's immediate first action, and promotion also requires the worst preflop-root BB/100 lower bound to clear `HOLDEM_PREFLOP_ROOT_PROMOTION_LCB_FLOOR` (default `-64`).

The matched-teacher budget also reserves `HOLDEM_PREFLOP_TEACHER_SHALLOW_OPEN_MIN_ROOTS` (default 12) across the 2bb–5bb open roots before extra comparisons follow the worst root. High-confidence matched branches use a small legal-action logit margin: it lowers a facing-4-bet call or shallow all-in only when teacher-supported alternatives score better on that same branch. The rule never masks a legal action. Adversarial collection reserves `HOLDEM_ADVERSARIAL_ROTATION_SHARE` (default 25%) for non-focused threats, so repeated trapper/calling-station focus cannot starve loose-aggressive or river-hunter tail-risk coverage.

If a run has collapsed, **Recover protected model** restores the newest `before-imitation-recovery-*` checkpoint instead of starting fresh. It archives the current primary/backup pair first, then runs a full fixed-seed audit of the restored model before allowing any new rollout. Approval requires direct, adversarial, holdout, forced-root, all-in, and fold-collapse safety floors; a merely non-folding checkpoint is not enough. Baseline metrics are immutable in the report, while failed-candidate metrics are recorded separately. An aggregate first-decision fixed-root fold rate of `HOLDEM_PREFLOP_ROOT_FOLD_COLLAPSE_RATE` (default `0.98`) restores every population member to the anchor and ends the current run only when that anchor is measured and passes the full safety floor. A fresh random model has no recovery anchor: the same signal is logged as `fresh_warmup_fold_collapse`, promotion remains held, and learning continues. PPO now rechecks KL after each optimizer step and restores the whole PPO update if it exceeds the hard limit. During recovery, full audits run every `HOLDEM_RECOVERY_FULL_EVALUATION_INTERVAL` updates (default `9`) until two non-degenerate audits pass, then return to the normal interval. Matched teacher branches can override the generic all-in ceiling only at `HOLDEM_PREFLOP_3BET_TEACHER_ALLIN_MIN_CONFIDENCE` (default `0.55`); lower-confidence all-in targets are redistributed among legal normal actions rather than masking a shove. Fixed-root reports include masked fold/call/raise/all-in probabilities alongside greedy actions.

When a report finds an early all-in collapse, focused blind, `facing_open_2bb` through `facing_open_5bb`, `facing_3bet`, and `facing_4bet` rollouts are paired primarily with tight-aggressive opponents (with nit coverage retained). On a bounded sample of these roots, the trainer clones the exact public state and deal, compares every legal fold, call, normal raise, and all-in action, then continues each branch greedily for a short horizon before using the critic leaf. The confidence-weighted result is a soft PPO action target—not a chart or action mask. A legal all-in is retained when its matched branch supports it; when it is demonstrably inferior, a contrastive logit term lowers only that unsafe shove. Reports include multi-raise teacher samples, target shove probability, observed shove rate, and matched non-all-in vetoes. Ordinary winning self-play decisions are no longer added to imitation replay, because replaying only winners biased the policy toward high-variance all-ins; explicitly validated offline teacher data remains eligible. Full evaluation defaults to every 27 PPO updates (`HOLDEM_FULL_EVALUATION_INTERVAL`) while cheap screening remains every update, and periodic checkpoints default to 20,000 hands. These reduce evaluation and checkpoint wall time without weakening promotion gates or reducing training hands.

Strategy snapshots now use a normalized distance across the policy path rather than the mean of one weight tensor. Near-duplicate snapshots are rejected under `HOLDEM_SNAPSHOT_MIN_DISTANCE` (default `0.001`); when more than six candidates remain, the archive retains the newest snapshot plus the maximally diverse set. This is a practical model-distance diversity control, not a proof that policies are strategically distinct.

The rollout backend remains batched Python and native-ready, now avoiding repeated arena scans and reusing immutable equity candidate sets across decisions that share visible cards. Full promotion evaluation records each holdout scenario's paired BB/100 bootstrap interval and paired-return variance; the worst holdout interval is an additional promotion gate. Exploiter threat is ranked from chip EV rather than hand-win rate. Training status exposes the requested and observed adversarial rollout share, adversarial BB/100 floor, and teacher mode so ablation runs can be compared fairly.

The UI **Quick 5K smoke test** option forces 5,000 hands, keeps normal per-update safety and root screening, and skips the expensive final promotion audit. Its report is marked `smoke_test: true` and `promotion_eligible: false`; use it to compare behavioral changes quickly, not to validate a deployable champion.

## Optional vectorized rollout primitives

Install the backend dependencies. The default `auto` backend selects the parity-tested compiled path when Numba is available and otherwise falls back to Python. You can still select it explicitly before starting the server:

```powershell
pip install -r backend/requirements.txt
$env:HOLDEM_ROLLOUT_BACKEND = 'compiled'
uvicorn backend.main:app --reload --port 8000
```

`vectorized` uses Numba-compiled array loops for seven-card hand scoring, sampled equity showdown batches, legal semantic action masks, and raise-size interpolation. `compiled` additionally batches semantic action-transition planning—stack/bet updates, raise bounds, and legal action resolution—before the reference game applies each plan. The full `HeadsUpHoldem` object remains the canonical source for cards, streets, public history, terminal settlement, and the browser protocol. Fixed-seed parity tests cover masks, transitions, raise rounding, showdowns, and hand scores. The first accelerated run includes Numba compilation time; later runs reuse the on-disk cache. Set `HOLDEM_ROLLOUT_BACKEND=python` to force the reference implementation. If Numba is unavailable, training reports `python-batched` and continues safely.

The single CUDA rollout worker builds each padded observation batch in contiguous pinned host memory and transfers each tensor once. Frozen champion, league, exploiter, and snapshot opponents are cached by exact process-local revision; learner and target weights still synchronize every update. A cache miss or stale revision fails closed before gameplay instead of using stale weights. Status and reports split model setup, arena setup, tensor preparation, inference dispatch, action post-processing, rule execution, worker time, dispatch wait, and verified cached-opponent counts.

## API overview

| Endpoint | Purpose |
| --- | --- |
| `GET /api/game` | Current game view, with opponent cards hidden until the hand ends. |
| `POST /api/game/new` | Reset stacks and deal a new match. |
| `POST /api/game/next` | Deal the next hand, retaining stacks. |
| `POST /api/game/action` | Submit `{ "action": "fold|check|call|raise|all_in", "amount"?: number }`. `amount` is the raise-to total for the betting round. |
| `POST /api/training/start` | Start background self-play with `{ "episodes": 1000, "fresh": false }`; set `fresh` to `true` to archive the current checkpoint pair and train a new model. |
| `POST /api/training/teacher-data` | Import a validated local JSONL filename from `backend/data/hand_history`. |
